# 网络同步：快速定位游戏对象感知范围

无论是本地单机游戏还是网络联机游戏，当玩家做出动作，程序进行响应时都需要保证尽可能快速及时。在网络模式下，对及时性的要求被无限地放大了。

在一般的网络联机游戏中，权威服务器决定世界运转的核心规则，不同玩家的客户端在功能上只充当了显示和输入设备。当玩家成功在服务端产生了新的行为动作时，为了确保联机逻辑的正确性，这些新的世界状态应该同步传输到其他玩家的设备上，从而尽可能确保在同一时空下、同一对局中的玩家看到的世界是一致的。

但随着游戏地图场景增大，游戏中玩家数量越来越多，这种对联网数据通信的带宽等性能要求是呈**平方级**的速度增加的。这就要求服务端应尽可能缩小游戏对象逻辑的关注范围，让要求不至于随着游戏玩家数而激增。

## AOI

AOI：Area Of Interest，叫做“动态范围感知”或“兴趣区域管理”。它不是简单的一个算法，更像是一个问题，而我们常有多种多样的算法解题思路来应对它。

### （1）简单粗暴法

直接为每一个游戏对象都绑定一个检测区域，借助物理系统，实现所有和动态范围感知有关的任务。

这种方法在单机或 P2P 联机模式游戏中还尚可一战，但在商业级的网络游戏中，会有很多弊端：

1.  首先，在服务器上为了 AOI 的实现而保留物理引擎，会占用大量 CPU 资源，得不偿失。
2.  其次，虽然开发小体量的联机游戏时，可以直接借助引擎导出 headless 无头服务端，即关闭了渲染等系统的专用服务器程序。但在商业网络游戏中，常常对系统的可扩展性、负载均衡能力和可监控性等架构层面有更高的要求。在这种情况下，服务端程序常使用专用的服务器框架，就更没有必要接入物理引擎了。

### （2）遍历法

当一个事件发生时，遍历世界中所有的游戏对象，将它的坐标差值进行比对，若小于等于 AOI 的感知范围，便将该对象缓存到 AOI 列表中，在下一网络帧中对该对象的游戏状态数据进行同步。

```cpp
void UpdateAOI(Entity* entity) {
    for (Entity* other : allEntities) {
        if (entity != other && Distance(entity, other) < VIEW_RANGE)
            AddToViewList(entity, other);
    }
}
```

但游戏世界中对象较多时，效率还是非常低下。

### （3）空间切割法

将游戏场景划分为多个规则的区域，如网格、四叉树或八叉树，让每个区域内只包含有限的实体。这样，玩家移动时，便仅需要查询其所在区域和相邻区域内的对象，从而在遍历检查的环节大大减少计算量。以网格算法为例。

```cpp
// 定义网格单元
struct Cell {
    vector<Entity*> entities;
};

// 初始化网格
const int GRID_WIDTH = 100;
const int GRID_HEIGHT = 100;
Cell grid[GRID_WIDTH][GRID_HEIGHT];
```

划分网格后，便可以用**九宫格**来描述游戏角色的关注区域。当想要获取该角色 AOI 范围内的其他对象时，只需要遍历以自身为中心周围 9 个网格中的对象即可。

```cpp
// 将实体添加到对应的网格单元中
void addEntity(Entity* entity) {
    int x = entity->posX / CELL_SIZE;
    int y = entity->posY / CELL_SIZE;
    grid[x][y].entities.push_back(entity);
}

// 更新实体在网格中的位置
void updateEntity(Entity* entity, float oldX, float oldY) {
    int oldCellX = oldX / CELL_SIZE;
    int oldCellY = oldY / CELL_SIZE;
    int newCellX = entity->posX / CELL_SIZE;
    int newCellY = entity->posY / CELL_SIZE;
    if (oldCellX != newCellX || oldCellY != newCellY) {
        removeEntityFromCell(entity, grid[oldCellX][oldCellY]);
        grid[newCellX][newCellY].entities.push_back(entity);
    }
}
```

当向游戏场景中新增对象时，首先根据实体的位置坐标，将其放入正确索引的网格中。当需要更新对象位置时，便需要同步修改其所属的网格，以确保当角色的位置改变时，场景中关注本角色对象的其他游戏对象也能够成功获取它的进入和离开通知。

```cpp
vector<Entity*> queryAOI(Entity* entity) {
    vector<Entity*> result;
    int cellX = entity->posX / CELL_SIZE;
    int cellY = entity->posY / CELL_SIZE;
    for (int i = cellX - 1; i <= cellX + 1; i++) {
        for (int j = cellY - 1; j <= cellY + 1; j++) {
            if (isValidCell(i, j)) {
                for (Entity* other : grid[i][j].entities) {
                    // 可在此处追加距离、视野等过滤条件
                    result.push_back(other);
                }
            }
        }
    }
    return result;
}
```

若要查询在某个实体 AOI 范围内的其他游戏对象实体，便可以借助网格的索引将扫描范围精准且快速地限定在周围的 3×3 网格范围内。当然还可以在真正决定其为 AOI 范围内的对象前，再加上游戏逻辑相关的判定。

但是空间越大，所需的世界网格就越多，相应的内存占用就越大。若仅只是世界变大，而玩家数量远小于空间网格数，这种 AOI 的效率甚至低于直接遍历对象。

### （4）十字链表算法

让 AOI 的计算消耗仅与玩家数量相关。

```cpp
struct Node {
    Entity* entity;
    Node* left;
    Node* right;
    Node* up;
    Node* down;
};

Node* head = nullptr;
```

十字链表由两条双向链表构成，其上的每一个节点，都可以进行上下左右四向检索，数据组成一张网状结构，顶点上存储着可能存在的对象，而非简单的两条链表。

```cpp
void insert(Entity* entity) {
    Node* newNode = new Node();
    newNode->entity = entity;
    // 需要同时维护行和列有序性
    Node* curr = head;
    Node* prev = nullptr;
    while (curr != nullptr && curr->entity->posX < entity->posX) {
        prev = curr;
        curr = curr->right;
    }
    // 插入节点到横向链表中
    newNode->right = curr;
    newNode->left = prev;
    if (prev) prev->right = newNode;
    if (curr) curr->left = newNode;
    if (!prev) head = newNode;

    // 同理，按Y坐标在纵向链表中插入
    // ... ...
}
```

向已有多个元素的世界中添加新的实体对象时，从网状链表的头部节点开始向着四个方向搜索，查找自身存在的位置。十字链表的关键在于**行与列的有序性**，也就是说横向排布的链表节点是按照 x 坐标方向顺序实现的，竖直方向排布的节点则按照 y 坐标方向顺序。在这两个方向上都为新节点找到了合适的位置后，AOI 检索便轻松很多了。

```cpp
vector<Entity*> query(float x, float y, float range) {
    vector<Entity*> result;

    // 第 1 步：快速跳过 posX < x - range 的节点（它们一定在范围外）
    Node* curr = head;
    while (curr && curr->entity->posX < x - range)
        curr = curr->right;

    // 第 2 步：扫描 [x - range, x + range] 区间，超出右边界立即停止
    while (curr && curr->entity->posX <= x + range) {
        if (fabs(curr->entity->posY - y) <= range)
            result.push_back(curr->entity);
        curr = curr->right;
    }
    // 一旦 posX > x + range，后面的节点 posX 更大，必然也在范围外 → 直接结束

    return result;
}
```

当需要进行 AOI 检索时，只需要保证该节点的 x 和 y 方向链表上存储的位置均存在于范围之内，即可快速筛选出有效的对象。

十字链表算法在计算 AOI 范围时，最大的好处便是**与空间大小无关**，同时避免了大量无效的遍历过程。

## AOI 的附加价值

AOI 在游戏中的作用也不止帮助服务器快速定位对象，或是减少数据同步量，还能保证反作弊的功能：仅将玩家当前拥有可视范围权限内的对象同步给玩家客户端，从而在网络数据层面提高了透视挂产生的门槛。
