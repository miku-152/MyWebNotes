# 对象池设计浅析

其实就是使用了一大块固定的内存当做池子，来存储我们可以重复使用的对象，来取代单独分配和释放对象，来得到提升性能和优化内存使用的目的。

当我们频繁创建和销毁大量游戏对象，就极有可能出现内存碎片。对象池除去减少内存分配和释放时的性能消耗外，在很多性能受限的平台，如移动端、嵌入式系统等，一个很关键的作用就是避免内存碎片化。

## 池中对象

```cpp
class Bullet
{
public:
    bool active;    // 是否正在使用
    float x, y;     // 子弹位置

    Bullet() : active(false), x(0), y(0) { }

    // 初始化子弹，设置起始位置并激活子弹
    void init(float startX, float startY)
    {
        active = true;
        x = startX;
        y = startY;
    }

    // 更新子弹位置（简单向右移动）
    void update()
    {
        if (active)
        {
            x += 1.0f;
            if (x > 100.0f)
                active = false;
        }
    }
};
```

对象池中的对象设计时的一个重点便是**正确地清空状态**，因为同一个对象的内存可能会被重复使用。

## 对象池的实现

```cpp
class BulletPool
{
private:
    std::vector<Bullet> pool(100);  // 对象池容器

public:
    // 获取一个可用的子弹对象
    Bullet* acquire()
    {
        // 遍历池中已有的子弹，寻找处于闲置状态的对象
        for (size_t i = 0; i < pool.size(); i++)
        {
            if (!pool[i].active)
                return &pool[i];
        }

        // 如果没有闲置对象，则新创建一个子弹并加入池中
        pool.push_back(Bullet());
        return &pool.back();
    }

    void updateAll()
    {
        for (size_t i = 0; i < pool.size(); i++)
        {
            if (pool[i].active)
                pool[i].update();
        }
    }

    void reset()
    {
        for (size_t i = 0; i < pool.size(); i++)
            pool[i].active = false;
    }
};
```

## 扩容策略

常见的设计中，我们可以按照**倍增**的策略去扩大对象池容量。譬如，对象池初始化时便申请了 100 个对象的内存大小，当这 100 个对象都已经被使用从而无法找到新的对象时，便申请 200 个对象大小的内存空间，并将已有的对象拷贝过去。

::: warning 注意
如果像示例这样用 STL 的容器实现对象池，那需要注意倍增策略是否与 STL 容器的自动扩容策略冲突。如果 `acquire` 对外返回的是容器中的对象地址，那么 STL 的自动扩容可能还会导致该指针失效。
:::

## 优缺点

**优点：**

1. 节省对象创建和销毁时的内存申请与释放性能消耗。
2. 避免频繁内存分配造成内存碎片问题。
3. 提升缓存命中率，性能更优。
4. 更易监控和统计内存相关的游戏性能数据。

**缺点：**

1. **内存预分配风险**：如何设计分配策略是危机四伏的。分配空间过大，可能导致性能浪费或分配失败；预分配不足，后续运行时频繁扩容产生的内存拷贝又会降低程序性能，适得其反。
2. **对象状态维护复杂**：要确保 `acquire` 接口返回的对象是一个没有残留先前状态的新对象，就像使用 `new` 重新分配得到的一样。
3. **架构设计成本高**：实际工作场景中，我们还需考虑多线程环境下，该如何安全地获取新对象或扩容。
