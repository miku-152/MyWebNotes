# 面向对象基础与原则

## 一、重载和重写的区别

1.  **重载（Overload）**
    *   在同一个作用域内定义多个同名的函数和运算符，但他们的参数列表不同。
    *   允许一个函数名根据参数的类型、数量或顺序来执行不同的操作。
    *   重载函数是根据**编译时**的参数类型来决定调用哪个版本的函数，叫做**静态绑定**。
2.  **重写（Override）**
    *   在子类中重新定义从父类继承过来的虚函数，允许子类修改父类方法的实现，达到**动态多态**的效果。
    *   重写函数的函数签名，包括函数名、参数类型和数量，必须与父类的虚函数完全相同。
    *   重写的函数是在**运行时**决定调用的，叫做**动态绑定**。

## 二、面向对象六大设计原则

### 1. 单一职责原则（Single Responsibility Principle）
一个类只能承担一种功能。
*   **优点**：
    1.  **降低耦合性**：当一个类只做一件事时，出问题也容易定位和修复。
    2.  **增强可读性和可维护性**：职责单一的类结构清晰，使得后期修改和功能拓展都变得更简单。
    3.  **复用性**：拆分不同职责后，每个类都可以在其他场景中重复使用。

### 2. 开闭原则（Open/Close Principle）
对扩展开发，对修改封闭。当需求改变时，应尽量通过扩展编写新的代码，而非修改已有的代码。
*   **优点**：
    1.  **预防性措施**：修改已经稳定的代码可能会引入新的bug，扩展可以降低风险。
    2.  **提高灵活性**：在游戏开发等需求多变的领域，通过扩展方式可以更好的应对需求变化。

### 3. 里氏替换原则（Liskov Substitution Principle）
要求所有父类出现的地方，都可以使用子类对象来替换，而不改变程序的正确性。
*   **优点**：
    1.  **保证继承体系的正确性**：如果子类不完全遵守父类契约，调用者可能会遇到意想不到的问题。
    2.  **提高代码复用性**：符合LSP的设计能使多态机制充分发挥作用，增强系统拓展性。
*   **实现要求**：
    1.  子类方法的参数类型必须与其父类的参数类型相匹配或更加抽象。
    2.  子类方法的返回值类型必须与父类方法的返回值类型或其子类别相匹配。
    3.  子类中的方法不应抛出基础方法预期之外的异常类型。
    4.  子类不应加强其前置条件。
    5.  子类不应削弱其后置条件。
    6.  父类中的不变量必须保留。
    7.  子类不能修改父类中私有成员变量的值。

### 4. 接口隔离原则（Interface Segregation Principle）
接口要小而专，不要大而全。

### 5. 依赖倒置原则（Dependency Inversion Principle）
高层次的类不应依赖低层次的类，而是将两者的依赖转嫁到抽象接口之上。低层次主要指底层架构，譬如文件IO、网络通信、数据库连接等。高层次主要是描述软件功能，业务逻辑，如按钮响应、界面显示等。

### 6. 迪米特法则（Law of Demeter）
也叫做最小知识原则，要求一个对象，只与其最直接关联的对象进行通信，而不和陌生对象进行耦合。
*   **优点**：
    1.  **降低耦合度**：减少对象之间的依赖，防止因某个对象的变化影响过多其他对象。
    2.  **增强系统稳定性**：每个模块只关注自己的直接关系，便于测试和维护。
